Wrap up the current task. Additional instructions: $ARGUMENTS

This template applies to `/wr` or an explicit request for full wrap-up. A request for only commit, push, comment or closure performs that action and its prerequisites, without triggering this whole workflow. Conversation instructions may narrow or override the steps below.

## Establish context

- Use only issues/PRs tied to the current task. If none apply, treat it as non-GitHub work.
- Inspect the worktree and branch before mutations. Full wrap-up defaults to `main`; if another branch has not already been authorized, ask which branch to use before committing or pushing. Do not switch branches automatically.
- Identify task-owned changes and any unrelated staged changes. Do not include unrelated work in the commit.
- For multiple linked issues, establish which issues the completed work resolves before adding closing references or closing them. Reuse explicit decisions already made in the conversation.

## Complete in order

1. Finish implementation and run the shared [checks](../CONTRIBUTING.md#checks) for the affected surfaces. Resolve failures before commit/push. If a required check cannot run, report the limitation and obtain a decision before proceeding unless the user has already allowed it.
2. Update `CHANGELOG.md` only when the task includes maintainer/release preparation, following [cl.md](cl.md). Ordinary wrap-up does not create a release section.
3. Commit only the task-owned files or hunks using the shared commit conventions. Never use `git add .` or `git add -A`; leave unrelated changes out of the commit. Include `closes #<issue>` only for an issue this completed work resolves. Do not add closing references to unrelated or incomplete work.
4. Push the authorized current branch without force.
5. For related GitHub work, if no final comment has been posted in this session, prepare and preview a concise comment containing the result and validation, then post it once after a successful push. End with this exact standalone line:

   ```text
   This comment is AI-generated by `/wr`
   ```

6. After a successful push, close a related issue with reason `completed` only if this work resolves it. Check its current state first; leave already closed issues closed. Do not close a PR through this step.

Do not create a PR unless explicitly requested. Do not post a GitHub comment for non-GitHub work, or duplicate a final comment unless the user asks for another. Report the commit, push result and any issue actions taken.
