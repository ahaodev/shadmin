# Frontend Patterns

React 19 + TS strict, Vite (SWC), TanStack Router/Query/Table, Zustand, React Hook Form + Zod 4, shadcn (Tailwind v4), Axios, Sonner. Reference implementation: `features/system/departments` (simple) and `features/system/users` (server-side pagination).

## Feature layout
```
frontend/src/features/system/<resources>/        # plural dir
├── index.tsx                          # page entry
├── components/
│   ├── <resources>-provider.tsx       # dialog state + currentRow
│   ├── <resources>-columns.tsx
│   ├── <resources>-table.tsx
│   ├── <resources>-dialogs.tsx        # renders all dialogs
│   ├── <resources>-action-dialog.tsx  # create/edit (one component)
│   ├── <resources>-delete-dialog.tsx
│   └── <resources>-primary-buttons.tsx
├── hooks/use-<resources>.ts           # queries + mutations
├── hooks/use-<resource>-form.ts       # form logic (optional)
└── data/schema.ts                     # Zod form schema
```
Match the shape of the closest existing feature; trim files you don't need.

## Types & services
- `types/<resource>.ts`: `snake_case` fields matching backend JSON; dates are `Date`; Go `*string` → optional field. Define entity, `Create*Request`, `Update*Request`.
- `services/<resource>Api.ts`: `apiClient` from `./config`, endpoint `/api/v1/{module}/{resource}`, return `response.data.data`, parse date strings in a `parseX()` converter. Re-export from `services/index.ts`.
- Query strings: `buildSearchParams(params)` from `@/lib/query-params` (skips empty values).
- `apiClient` already injects the Bearer token, refreshes on 401 and retries; don't reimplement.

## Hooks (`hooks/use-<resources>.ts`)
- Query key constant (`const KEY = 'departments'`); `useQuery({ queryKey: [KEY, params], queryFn, staleTime: 5 * 60 * 1000 })`; `enabled: !!id` for single items.
- Mutations: `useCrudMutation({ mutationFn, queryKeys: [[KEY]], successMessage, errorMessage })` from `@/hooks/use-crud-mutation` — handles invalidation, toast and error message (`getErrorMessage` from `@/lib/error`). Batch delete: `Promise.all(ids.map(del))`.

## Provider & dialogs
- Provider: `const [open, setOpen] = useDialogState<'add'|'edit'|'delete'>(null)` (default export of `@/hooks/use-dialog-state`; `setOpen(x)` toggles) + `currentRow` state; export `<XProvider>` and `useX()` that throws outside the provider.
- `*-dialogs.tsx`: add dialog always rendered; edit/delete wrapped in `currentRow && (...)` with a `key` including the row id; on close `setTimeout(() => setCurrentRow(null), 500)` so the close animation finishes.
- Action dialog: `isEdit = !!currentRow`; one form for create and edit; reset the form when `currentRow` changes; submit via create/update mutation.

## Table
- Server-side: `manualPagination: true`, `manualFiltering: true`, `pageCount = Math.ceil(totalCount / pageSize)`.
- `useTableUrlState({ search, navigate, pagination, columnFilters })` syncs URL ↔ table. Its default URL keys are `page` / `pageSize`; map them to API `page` / `page_size` in `index.tsx`.
- `getRouteApi('/_authenticated/system/<resource>')` for typed `useSearch()` / `useNavigate()`.
- Columns: select checkbox, data, actions (edit/delete gated by `hasPermission`).

## Page (`index.tsx`)
`<XProvider>` wraps `<PageHeader fixed />`, `<Main>` (title + `<XPrimaryButtons />` + table) and `<XDialogs />`. Server-paged pages render Skeleton → error → table.

## Schemas (`data/schema.ts`)
Zod form schema with `.min(1, '…')` for required fields; export `z.infer` types. API-response schemas (if needed) use `z.coerce.date()`.

## Route file (`routes/_authenticated/system/<name>.tsx`)
```ts
const searchSchema = z.object({
  page: z.number().optional().catch(1),
  pageSize: z.number().optional().catch(10),   // key must match useTableUrlState
  // resource filters ...
})
export const Route = createFileRoute('/_authenticated/system/<name>')({
  validateSearch: searchSchema,
  component: Resource,
})
```
- `.catch(default)` tolerates malformed URLs.
- The URL must equal the menu `path` seeded/created in the backend.
- `routeTree.gen.ts` is git-ignored and regenerated by `pnpm dev` / `pnpm build`.

## Permissions
`constants/permissions.ts`:
```ts
SYSTEM: { RESOURCE: { ADD: 'system:resource:add', EDIT: 'system:resource:edit', DELETE: 'system:resource:delete' } }
```
Use `const { hasPermission, hasAnyPermission, hasAllPermissions } = usePermission()` (`hooks/usePermission.ts`) and conditionally render — no wrapper component. Logic lives in `lib/permissions.ts` (exact match + `*` segment wildcards; admins bypass). Permissions come from `/api/v1/resources` into `auth-store`.

## Naming & imports
| Type | Convention | Example |
|---|---|---|
| Component files | `kebab-case.tsx`, PascalCase export | `users-table.tsx` |
| Hooks | `use-kebab-case.ts` (existing `usePermission.ts` is legacy) | `use-users.ts` |
| Services | `camelCaseApi.ts` | `departmentApi.ts` |
| Types | `kebab-case.ts` | `login-log.ts` |

Use the `@/` alias; relative paths only `./` inside a feature. Import order is enforced by Prettier (`pnpm format`).
